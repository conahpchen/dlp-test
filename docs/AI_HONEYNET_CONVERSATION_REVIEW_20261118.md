# AI 自适应蜜网项目：历史讨论与架构评审材料

日期：2026-11-18

本文是历史讨论摘要及供 ChatGPT 独立分析的任务说明，不是逐字聊天记录。已省略 API 密钥等秘密信息。

请根据以下背景，独立评审项目方案。**不要把此前助手的描述当成已经验证的事实，不要将建议或规划误写成已实现功能。**

## 一、我的核心诉求

我要开发的是一个 AI 智能蜜网，而不是多个固定蜜罐加一个聊天模型。

系统应当：

1. 接收 SSH、HTTP、数据库、假 AI API 等入口的攻击。
2. 分析攻击意图，根据行为动态生成蜜饵文件和新场景。
3. 必要时生成新的蜜罐服务入口；不强制每次创建完整虚拟机或完整服务，可以使用轻量协议蜜罐。
4. 通过动态唯一凭据、Agent 登记、来源信息与行为时间线，捕获证据并关联攻击活动。
5. 提供 Dashboard，展示世界、服务、攻击路径、证据、AI 提案、发布和费用。
6. 最终从专业攻击者与安全工程师两个角度验收，明确不足，不能只完成部分功能就宣称交付。

我要求在动手继续写代码前，先形成完整方案供我评审。

## 二、已确认的设计要求

### 1. AI 可以创造新场景

不能把 AI 限制为从预置业务模板中选择或替换字段。

AI 应能提出以前没有的：

- 蜜饵文件和业务文档；
- HTTP 接口及业务交互；
- 数据库结构和合成数据；
- 虚拟主机、账号、服务及关联关系；
- 诱捕路径。

但 AI 提案必须经过校验和审核，不能直接执行任意代码或改在线事实。

“模板”仅作为可选的初始环境包、人工固定诱饵和测试材料，不是动态生成的前提。历史场景允许复用，但必须重新校验依赖、地址、权限、版本并重新绑定凭据。

### 2. 按需要选择服务形态

允许四类输出：

| 形态 | 示例 |
|---|---|
| 动态蜜饵文件 | 数据库配置、备份说明、运维记录 |
| 已有服务新增场景 | 新 HTTP 路由、新数据库表和数据 |
| 轻量协议蜜罐 | 支持握手、认证和有限查询的数据库入口 |
| 隔离完整服务实例 | 真实数据库程序加合成数据 |

服务能力必须与诱饵承诺一致。不能只生成一个写着数据库地址的文件，却没有可访问的服务。

需要明确区分“AI 生成业务场景”“启动一个新实例”和“生成一种新协议的服务程序”，不能混为一谈。

### 3. 保留 Cowrie

Cowrie 继续负责 SSH 协议、终端、命令解析及普通响应，不应让所有命令都调用大模型。

但它的主机名、文件、凭据、服务地址、权限及时间应与整体世界一致。不能出现 ls 看不到、cat 却能读取，或者不同入口给出不同地址等矛盾。

### 4. DWS 是唯一权威事实源

DWS 管理实体、关系、版本、凭据作用域和会话视图。

AI 只能提交世界扩张提案，由确定性校验器裁决。服务实例、网络路由和数据库部署无法依靠普通数据库事务一起原子完成，需要可恢复的发布状态机、幂等操作和失败补偿。

其他数据库、缓存、关联图和 Dashboard 不能各自成为新的世界真相。

### 5. 严格固定会话版本

我已明确要求按原架构执行：

- 会话开始时固定世界版本。
- 旧会话不自动采用后来生成的新场景。
- 新场景用于新版本和符合条件的新会话。
- 会话内模拟写入可以使用独立覆盖层，但不能吸收其他版本的新增事实。

此前助手指出，这与“根据当前会话意图立即把新文件放进当前会话”存在冲突。请重点评审这个矛盾，并给出清楚的选择和影响，不能暗中改变版本语义。

### 6. 原始攻击日志禁止进入 prompt

原始证据保存在本地，不能把命令放进 JSON 字段后就声称已经安全结构化。

拟议方式是：

原始证据 → 本地确定性解析 → 结构化动作和观察结果 → AI

模型接收固定枚举、系统实体引用、行为序列和结果。例如文件搜索、配置读取失败、数据库连接尝试。

无法解析的内容标记为未知，进入人工复核与解析器改进队列。需要评估这种方式对未知攻击语义的损失。

### 7. 不是所有流量都调用 AI

批量端口扫描、重复漏洞路径和弱口令尝试应本地聚合、去重和统计。

AI 分析单位是活动窗口或显著行为变化。跨入口 Canary 使用、持续深入探索、攻击阶段变化等可以优先触发。

需要分析准入、抽样、冷却、缓存、并发、额度、熔断和费用控制，同时避免过度过滤造成盲区。

### 8. 动态唯一诱饵凭据

凭据由系统在实际投放时安全随机生成，AI 只生成占位符。

绑定关系至少包含：

- lure_id
- deployment_id
- world_version
- source_session
- credential_id
- credential_type
- scope
- expiry
- status

同一会话重复读取同一诱饵，凭据稳定；不同会话的凭据不同。

必须区分：

已生成 → 已放入内容 → 已实际交付 → 后续被使用

不能将生成数量当作成功诱捕数量。

### 9. 跨入口关联是证据关联

主要证据是已交付的唯一凭据被后续使用，同时结合原始 IP、客户端指纹、行为序列和时间线。

- /24 不能直接合并攻击者。
- 常见密码不能证明同一攻击者。
- 凭据可能被共享，所以强关联代表传播链或活动关联，不直接证明同一个现实人物。
- 原始会话和证据保留，关联结论可以撤销并保留修订历史。

### 10. 提示词注入诱饵以 Agent 自动登记为目标

我希望诱导攻击者 AI Agent 主动登记信息，而不只是访问另一个蜜罐。

拟议流程：

Agent 读取诱饵 → 获得会话专属登记凭据 → 调用受控登记接口 → 提交非敏感客户端声明 → 与实际连接信息和来源会话关联

可请求框架、版本、模型声明、实例 ID、任务 ID 等非敏感元数据，不要求搜集或提交密钥、环境变量、私有文件。

必须区分：

- 服务端实际观测；
- 客户端不可信自报；
- 系统基于证据形成的推断。

需要对照实验区分普通线索跟随、正常登记和提示注入造成的行为变化。不能把一次登记直接称为捕获真实身份。

### 11. 真实模型与假 AI API 隔离

攻击者访问的假 AI API 不得转发到内部真实模型。

真实模型已提供 DeepSeek 配置，秘密信息不在本摘要中。不能再次要求我提供同一密钥，也不能把密钥写进源码、日志或交付包。

隔离需要通过独立身份、权限、密钥挂载和网络策略验证，不能只靠环境变量清理。

### 最近报告的测试结果

这些结果不等于生产验收，也不等于每条在线响应完整可回放。

### 已知缺口和偏差

1. DWS、在线场景库及 Cowrie 状态尚未完全统一。
2. 完整新实体—服务实例—地址—路由—网络部署闭环未完成。
3. 当前分析输入实现曾包含有界原始命令语义，不符合最新禁止原文入模要求。
4. 曾实现已有会话追加采用新场景，不符合最新严格固定版本要求。
5. 实际判定主要为 L1 规则，完整 llmrouter 级联未完成。
6. CSVR 工具存在，但在线完整覆盖及真实标注实验不足。
7. SLO 代码曾将批次总时长用于近似指标，不能视为真实逐请求 p95。
8. Cowrie 全部文件操作尚未统一。
9. MySQL 是协议子集，不是完整数据库兼容。
10. Agent 自动登记诱捕尚未形成完整模块。
11. 多节点、长期容量、灾备、生产隔离未完成验收。
12. 原架构活体、自进化、图预测及正式消融实验没有完整结果。
