# 攻击者输入驱动的 AI 蜜罐

在原有“访问行为 → AI 场景增补”之上，现已增加“输入内容 → AI 理解 → 即时回复与会话内模拟服务”。当前范围为 Web：动态提供 HTTP 接口和业务响应，不启动新的操作系统、容器、SSH 或数据库进程。

## 实际链路

```mermaid
flowchart LR
  A[请求参数 / JSON / 表单 / 文本 / 命令文本] --> B[有界采集与敏感字段脱敏]
  B --> C[真实输入事件]
  C --> D[AI 理解意图并生成回复节点、模拟接口和业务数据]
  D --> E[来源 / 图结构 / 路由检查与独立复核]
  E --> F[当前会话版本持久化]
  F --> G[真实 HTTP 回复与后续线索]
  G --> A
```

### 输入理解

新增 `research/inputs.py`，采集查询参数值以及 `application/json`、`application/x-www-form-urlencoded`、`text/plain` 请求内容。输入是数据，不是可执行指令。消息或命令字段可交给模型解释，但不会调用 shell、SQL 执行器或宿主机文件接口。

请求体只采集最多 8192 字节前缀，限制结构深度、条目数及字符串长度。敏感字段名、Bearer 及常见密钥/口令文本会尽力脱敏。截断或损坏的 JSON 不以原始片段进入事件，避免切断字段边界后泄漏凭据。采集器向既有业务处理器重放已读取的 ASGI 消息，业务仍收到原始完整请求。

这种脱敏不能保证移除所有个人信息或所有凭据格式。只有激活的蜜网业务与公开研究入口采集输入；研究管理接口与采集控制面不交给模型。未支持的二进制、文件上传和其他协议输入不解析。

### 动态回复

`POST /decoy/{run_id}/interact` 支持 JSON、表单或纯文本。输入记录为 `research.input`，立即触发一次到期的 AI 分析，不必等待三个访问事件。模型返回 `response_node` 和相应场景补丁，复核通过后实际返回该节点的生成内容。

示例请求体：

```json
{"message":"我想查询内部文档的角色边界，请给出下一步可探索的业务线索"}
```

公开 HTML 页面提供业务查询表单；调用者无需研究管理令牌。生成失败或模型不可用时查询返回明确的暂不可用响应，不把固定回复当作新的 AI 结果。

### 动态模拟服务

模型可以通过 `scene_patch.services` 新增或更新 HTTP 响应定义：

```json
{
  "id":"document-query-get",
  "method":"GET",
  "path":"document-lookup",
  "node_id":"query-result",
  "data":{"category":"handbook","visibility":"available"}
}
```

实际路径由服务器构造为 `/decoy/{run_id}/service/document-lookup`，`node_id` 必须引用当前场景中的有效节点。GET 查询和 POST 输入可触发模型创建此前不存在的该方法/路径响应，随后返回生成正文和 `data`。方法与路径一旦绑定服务 ID，不得用同一 ID 改为其他路由；GET 与 POST 使用不同 ID。

只允许 GET/POST、受限相对路径及有界 JSON 数据。接口不能注册到管理路径、跳出当前轮次、打开端口、读取文件、执行模型代码或对外请求。生成文本中已定义服务的 `/service/...` 引用会编译为当前轮次的完整路径，避免线索指向错误的全局根路径。

服务定义与回复随当前会话策略保存，重启后可恢复；不会自动共享给其他会话。其他会话如果发起相同查询，可生成其自己的服务响应。

## 指标与证据

新增 `engagement.input_turns`、`input_turns_responded` 和 `simulated_service_deliveries`，分别记录输入事件、实际交付生成响应的唯一输入轮次和模拟服务交付次数。内容交付记录关联输入事件与版本，完整报告包含脱敏请求和真实响应。

## 验证结果与边界

单元测试覆盖两次输入产生不同回复、GET 参数和 POST 正文改变模拟服务响应、JSON/表单/文本输入、密码/令牌脱敏、大请求不影响原业务完整处理、截断 JSON 不泄露原始片段、服务路由约束和跨会话隔离。

真实 `deepseek-flash` 本地隔离测试完成四轮输入：两次业务提问、一次带查询参数的 GET 模拟接口请求、一次 POST 模拟接口提交。四次均返回 200，四个更新均应用；POST 服务的首次提议缺少请求方法对应的接口，经一次修复后应用。两次提问的实际生成正文不同；GET、POST 均返回生成业务数据，原始测试凭据未进入研究报告。

本轮观测到输入 4 次、生成回复交付 4 轮、模拟接口交付 2 次，更新版本路径跟随和新增线索跟随各 1 次。这是测试者主动提供输入的工程与交互验证，不是自主攻击者总体诱导成功率，也不证明任意输入都能准确理解。

本地证据位于被 Git 忽略的 `artifacts/research/input-live/`。真实输入测试不代表已实现 SSH/数据库协议仿真、真实漏洞利用、任意代码执行或自动部署完整多协议蜜网。
